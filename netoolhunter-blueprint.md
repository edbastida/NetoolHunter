# NetoolHunter — Blueprint

> Generated by The Architect on 2026-05-01
> Archetype: Mobile App (Android nativo, single-user, root-required)

---

## 1. Project Overview

### Vision
**NetoolHunter** es una app Android nativa que actúa como gestor visual de herramientas de pentesting para entornos Kali NetHunter. El usuario navega un catálogo curado de ~95 herramientas (apt, Go, pip, pipx, git, docker, scripts), las instala con un tap, y ve el output del proceso en tiempo real desde un terminal embebido. También gestiona los repositorios apt del chroot Kali (activar/desactivar/añadir custom) y la lista de tools instaladas (con desinstalación).

Sustituye el flujo manual de "abrir Termux → `nh -r` → recordar el comando exacto → copiar-pegar" por una UX de tienda de apps.

### Goals
- Instalar cualquier herramienta del catálogo en ≤2 taps desde Home.
- Mostrar output de instalación línea-a-línea en tiempo real (no esperar a que termine).
- Gestionar `sources.list` del chroot Kali sin editor de texto.
- Detectar correctamente qué tools están instaladas (cada tipo: apt, go, pip, etc.).
- Funcionar 100% offline tras la primera instalación (catálogo hardcoded).

### Success Metrics
- App arranca en <1.5s en dispositivo medio (Snapdragon 7xx).
- Output del terminal aparece con latencia <200ms desde que el comando lo emite.
- 0 crashes al perder/recuperar conexión durante una instalación larga.

**`Installer`** (sealed class — la pieza clave)
```kotlin
sealed class Installer {
    data class Apt(val pkg: String) : Installer()
    data class Go(val module: String) : Installer()           // go install <module>
    data class Pip(val pkg: String) : Installer()             // pip install <pkg> --break-system-packages
    data class Pipx(val source: String) : Installer()         // pipx install <source>
    data class Git(
        val repo: String,
        val cloneTo: String? = null,                          // si null, /opt/<reponame>
        val postInstall: List<String> = emptyList()           // ej. ["pip install -r requirements.txt --break-system-packages"]
    ) : Installer()
    data class Docker(val image: String, val runArgs: String = "") : Installer()
    data class Script(val curlUrl: String) : Installer()      // curl <url> | sudo bash
}
```

**`InstallEvent`** (lo que emite ShellExecutor)
```kotlin
sealed class InstallEvent {
    data class Started(val command: String) : InstallEvent()
    data class Stdout(val line: String) : InstallEvent()
    data class Stderr(val line: String) : InstallEvent()
    data class Exit(val code: Int) : InstallEvent()
    data class Error(val message: String) : InstallEvent()    // ej. "su no disponible"
}
```

### Persistencia (DataStore Preferences)

Solo 3 keys persisten:
- `enabled_repos: Set<String>` — IDs de repos activos
- `custom_repos_json: String` — JSON serializado de Repos custom
- `prereqs_completed: Boolean` — true tras pasar el wizard de prerequisitos

**No persistimos `installed`** — se detecta en cada arranque ejecutando los checks (más confiable que un cache que se desincroniza).

## 5. Shell Layer

### `ShellExecutor`

```kotlin
class ShellExecutor {
    /** Ejecuta un comando como root y emite eventos en tiempo real. */
    fun exec(command: String): Flow<InstallEvent> = channelFlow {
        send(InstallEvent.Started(command))
        try {
            val process = Runtime.getRuntime().exec(arrayOf("su", "-c", command))
            val stdoutJob = launch(Dispatchers.IO) {
                process.inputStream.bufferedReader().useLines { lines ->
                    lines.forEach { trySend(InstallEvent.Stdout(it)) }
                }
            }
            val stderrJob = launch(Dispatchers.IO) {
                process.errorStream.bufferedReader().useLines { lines ->
                    lines.forEach { trySend(InstallEvent.Stderr(it)) }
                }
            }
            stdoutJob.join()
            stderrJob.join()
            val code = process.waitFor()
            send(InstallEvent.Exit(code))
        } catch (t: Throwable) {
            send(InstallEvent.Error(t.message ?: "unknown error"))
        }
    }.flowOn(Dispatchers.IO)

    /** Wrapper para comandos dentro del chroot Kali. */
    fun execInKali(command: String): Flow<InstallEvent> =
        exec("nh -r '${command.replace("'", "'\\''")}'")
}
```

### `KaliCommand` builder

Convierte un `Installer` en el string de comando real:

```kotlin
object KaliCommand {
    fun install(installer: Installer): String = when (installer) {
        is Installer.Apt    -> "apt-get install -y ${installer.pkg}"
        is Installer.Go     -> "go install ${installer.module}"
        is Installer.Pip    -> "pip install ${installer.pkg} --break-system-packages"
        is Installer.Pipx   -> "pipx install ${installer.source}"
        is Installer.Git    -> buildGitCommand(installer)
        is Installer.Docker -> "docker pull ${installer.image}"
        is Installer.Script -> "curl -sSL ${installer.curlUrl} | bash"
    }

    fun uninstall(tool: Tool): String = when (val i = tool.installer) {
        is Installer.Apt    -> "apt-get remove -y ${i.pkg}"
        is Installer.Go     -> "rm -f $(go env GOPATH)/bin/${tool.id}"
        is Installer.Pip    -> "pip uninstall -y ${i.pkg} --break-system-packages"
        is Installer.Pipx   -> "pipx uninstall ${tool.id}"
        is Installer.Git    -> "rm -rf ${i.cloneTo ?: "/opt/${tool.id}"}"
        is Installer.Docker -> "docker rmi ${i.image}"
        is Installer.Script -> "echo 'Desinstalación manual requerida para ${tool.name}'"
    }

    fun isInstalled(tool: Tool): String = when (val i = tool.installer) {
        is Installer.Apt    -> "dpkg -l ${i.pkg} 2>/dev/null | grep -q '^ii'"
        is Installer.Go     -> "test -x $(go env GOPATH)/bin/${tool.id}"
        is Installer.Pip    -> "pip show ${i.pkg} >/dev/null 2>&1"
        is Installer.Pipx   -> "pipx list 2>/dev/null | grep -qi ${tool.id}"
        is Installer.Git    -> "test -d ${i.cloneTo ?: "/opt/${tool.id}"}"
        is Installer.Docker -> "docker images -q ${i.image} | grep -q ."
        is Installer.Script -> "which ${tool.id} >/dev/null 2>&1"
    }

    private fun buildGitCommand(g: Installer.Git): String {
        val target = g.cloneTo ?: "/opt/$(basename ${g.repo} .git)"
        val clone = "git clone ${g.repo} $target"
        val post = g.postInstall.joinToString(" && ") { "cd $target && $it" }
        return if (post.isBlank()) clone else "$clone && $post"
    }
}
```

```kotlin
object DefaultRepos {

             enabled = false, isCustom = false),

             "# BlackArch — solo notas, no se aplica a apt directamente",
             enabled = false, isCustom = false)
    )

```

### Flujo de "Aplicar cambios"

1. Lee la lista actual de Repos (default + custom) desde `ReposRepository`.
2. Filtra solo los `enabled = true`.
3. Construye contenido del archivo:
   ```
   # Generado por NetoolHunter — 2026-05-01
   <sourceLine 1>
   <sourceLine 2>
   ...
   ```
4. Backup del archivo actual: `cp /data/local/nhsystem/kali-arm64/etc/apt/sources.list /data/local/nhsystem/kali-arm64/etc/apt/sources.list.bak`
5. Escribe el nuevo contenido vía heredoc:
   ```
   nh -r 'cat > /etc/apt/sources.list <<EOF
   <contenido>
   EOF'
   ```
6. Ejecuta `nh -r 'apt-get update'` y muestra output en `TerminalScreen`.
7. Toast/snackbar: "Repositorios aplicados ✓".

### Bottom Navigation (5 tabs)


PrerequisitesScreen NO está en BottomBar — se muestra como overlay/modal en first-run.

### Component hierarchy (ToolsScreen)

```
ToolsScreen
├── TopAppBar
│   ├── BackIcon (si vino de Home con cat)
│   ├── Title "Herramientas"
│   └── SearchAction → expande a SearchBar
├── CategoryFilterRow (LazyRow de Chips, multi-select)
└── LazyColumn
    └── ToolCard (× N)
        ├── EmojiIcon (32sp)
        ├── Column
        │   ├── Text(name, titleMedium)
        │   ├── Text(description, bodySmall, alpha 0.7)
        │   └── Row { BadgeCategory; BadgeInstaller("apt"|"go"|...) }
        └── Button "Instalar" / "Instalado ✓" / CircularProgress
```

### State Management

- Cada pantalla tiene su `ViewModel` con `StateFlow<UiState>`.
- `UiState` es `data class` con todos los campos que la pantalla necesita.
- Compose colecta con `collectAsStateWithLifecycle()`.
- Acciones del usuario van a métodos del VM (`onInstallClick(tool)`).
- VM lanza `viewModelScope.launch { ... }` que llama a `Repository`/`ShellExecutor`.

### Terminal — flujo de instalación

1. User pulsa "Instalar" en `ToolCard`.
2. `ToolsViewModel.install(tool)` → emite a `TerminalBus` (singleton `MutableSharedFlow<InstallEvent>`).
3. Navega a `terminal`.
4. `TerminalViewModel` colecta `TerminalBus` y acumula líneas en `state.lines: List<TerminalLine>`.
5. `TerminalView` (LazyColumn con `reverseLayout = false`) auto-scrollea al final con `LaunchedEffect(lines.size) { listState.animateScrollToItem(lines.lastIndex) }`.

`TerminalBus` es global (object singleton) porque la instalación debe sobrevivir a cambios de pantalla y permitir lanzar instalaciones desde múltiples sitios (ToolsScreen, InstalledScreen, ReposScreen).

### Paso 7 — TerminalBus (singleton)

```kotlin
object TerminalBus {
    private val _events = MutableSharedFlow<InstallEvent>(
        replay = 0,
        extraBufferCapacity = 1024,
        onBufferOverflow = BufferOverflow.DROP_OLDEST
    )
    val events: SharedFlow<InstallEvent> = _events.asSharedFlow()
    suspend fun emit(event: InstallEvent) = _events.emit(event)
}
```

### Paso 8 — Foreground Service

`shell/InstallForegroundService.kt`. Lanza el comando, lo wirea a `TerminalBus`, mantiene una notificación con el nombre de la herramienta. Se para cuando recibe `Exit`. Necesario para que instalaciones largas (Metasploit, MobSF Docker pull) sobrevivan al lock screen.

```markdown
## Architecture

### Estructura
- `domain/` — Modelos puros (Tool, Category, Installer sealed, Repo, InstallEvent). Sin deps Android.
- `data/` — ToolsCatalog (hardcoded), DefaultRepos, ReposRepository, InstalledRepository, PrerequisitesChecker.
- `shell/` — ShellExecutor (Flow<InstallEvent>), KaliCommand (Installer→String), RootChecker, InstallForegroundService.
- `ui/screens/<screen>/` — Pareja Screen.kt + ViewModel.kt por pantalla.
- `ui/components/` — Componentes reutilizables (ToolCard, TerminalView, etc.).
- `ui/navigation/` — Routes (sealed), BottomBar, NavHost.
- `ui/theme/` — Color, Type, Theme.

### Data flow
```
ToolCard.onInstall(tool)
  → ToolsViewModel.install(tool)
    → InstallForegroundService.start(KaliCommand.install(tool.installer))
      → ShellExecutor.execInKali(cmd) emite Flow<InstallEvent>
        → TerminalBus.emit(event)
          → TerminalViewModel colecta y actualiza state.lines
            → TerminalView lo renderiza
```

`TerminalBus` es un `object` singleton con `MutableSharedFlow<InstallEvent>`. Es el único state global. Todo lo demás vive en ViewModels.

### Key patterns
- Un ViewModel por pantalla, expone `StateFlow<UiState>`.
- Compose recolecta con `collectAsStateWithLifecycle()`.
- Comandos shell siempre via `KaliCommand.install/uninstall/isInstalled` — nunca strings inline.
- `ShellExecutor.execInKali` envuelve con `nh -r '...'`. Nunca llamar `exec` directo para comandos del chroot.
- Detección de instalado se hace **on-demand** en InstalledScreen, no se cachea.

## Code Organization Rules

1. **Una clase por archivo.** Max 300 líneas. Si supera, extraer.
2. **Package alias:** importa absoluto `com.netoolhunter.app.*`. No barrel exports.
3. **Composables stateless.** Estado en ViewModel, pasa down como parámetros, callbacks up.
4. **Sin `LiveData`.** Solo `StateFlow`/`SharedFlow`.
5. **Sin Hilt/Koin.** Constructor injection manual desde `MainActivity`/`NetoolHunterApp`.
6. **Strings en `strings.xml`** — sin hardcodear en composables (excepto emojis/símbolos).
7. **Operaciones largas en `viewModelScope` con `Dispatchers.IO`.**
```

## 17. Reglas No Negociables (del proyecto)

1. **`nh -r` para TODO comando del chroot.** Nunca llamar `apt`, `pip`, `go install` directamente desde el shell de Android — fallarán porque viven en el chroot.
2. **Backup de `sources.list` ANTES de sobrescribir.** El usuario puede tener config custom. Perderla es romper su sistema.
3. **Confirm dialog antes de Aplicar repos / Desinstalar / Instalar prerequisitos.** Acciones destructivas o que escriben en el sistema requieren intent explícito.
4. **InstallForegroundService es obligatorio para instalaciones.** Sin él, lock screen mata `apt install metasploit-framework` (que tarda 10 min) y rompe el chroot.
5. **El catálogo es código, no datos.** `ToolsCatalog.kt` se compila con la app. Añadir tools = nueva versión. Esto es intencional: garantiza que comandos hardcoded no vengan de fuente externa manipulable.
6. **No cachear "instalado".** Detectar siempre con `KaliCommand.isInstalled` ejecutado en vivo. Cachear lleva a desincronización con el chroot real.
7. **Sin red en runtime.** App 100% offline tras la primera instalación. Cero analytics, cero telemetría, cero updates OTA.
8. **Dark theme forzado.** No `dynamicColor`. La identidad visual depende de la paleta Kali fija.
9. **Single Activity + Compose Navigation.** Sin Fragments, sin XML layouts.
10. **Si el device no tiene root → app no funciona.** PrerequisitesScreen lo bloquea explícitamente con mensaje claro. No hay fallback ni "modo demo".
